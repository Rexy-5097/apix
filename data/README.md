# `data/` — what each file is, and what it is not

Four files. **One of them is the source of truth; the other three are generated
from it or from a synthetic fixture.** If any two ever disagree, the store wins,
then `panel.json`.

| File | Kind | Generated by |
|---|---|---|
| [`panel.json`](panel.json) | **Canonical contract** | `tools/analysis/build_panel_json.py` |
| [`dashboard.html`](dashboard.html) | Presentation artifact | `tools/analysis/build_dashboard.py` |
| [`panel_report.txt`](panel_report.txt) | Audit/report artifact | `tools/analysis/panel_report.py` |
| [`engine-validation.html`](engine-validation.html) | **Synthetic fixture demo** | `tools/analysis/engine_demo.py --html` |
| [`mospi_cpi_airfare.json`](mospi_cpi_airfare.json) | External reference | `tools/analysis/pull_mospi_benchmark.py` |
| `collection/` | The SQLite store (gitignored) | the collection bridge |

---

## `panel.json` — the canonical observed-panel contract

**The sole source of truth for real-market observations.** Generated from the
SQLite store at `data/collection/collection.sqlite3`, and the only file the
dashboard and the report read. Nothing else in this repository is an independent
dataset of the panel.

It holds the **35 real observations** collected 2026-09-12 on DEL–BOM / IndiGo,
plus everything derived from them: the descriptive APW profile, the band profile,
quality counts, provenance grading, exclusions and the index-feasibility status.

`data_class: REAL_MARKET_OBSERVATION` · `synthetic_data_present: false`

Two earlier files, `apw_profile.json` and `observations_table.json`, were
**removed**: they duplicated this contract, were outside the generation pipeline,
and could therefore drift from it silently.

## `dashboard.html` and `panel_report.txt` — generated, not datasets

Both are rendered **from `panel.json`**; `panel_report.txt` additionally
recomputes from the store, so the two act as a cross-check on each other. Neither
is an independent source. Do not cite a number from them without tracing it to
`panel.json` — see [`docs/capability-matrix.md`](../docs/capability-matrix.md).

**No APIx market index value appears in either.** The index is `PENDING`:
methodology §C.1 requires a matched `t / t−7` pair and only one collection wave
exists. First possible matched pair: **2026-09-19**.

## `engine-validation.html` — synthetic, and never market data

Generated by running the **real index engine** over the controlled 14-day fixture
defined in `tests/test_pipeline_14_day.py`. Every value on that page is
**synthetic test data**, expressed in index points on a base of 100, with no
currency figures anywhere.

> **Nothing on that page is an airfare observation, and nothing on it is an APIx
> index value.** It exists to show that the engine computes, chains and refuses
> correctly — not to say anything about prices.

It is deliberately a separate file, never merged into `dashboard.html`, and a
test asserts that boundary holds.

## `mospi_cpi_airfare.json` — reference only

The official MoSPI CPI airfare series (`role: REFERENCE_ONLY`,
`is_apix_input: false`).

- It is **not** an input to any APIx calculation.
- It does **not** validate the APIx panel — a national CPI series cannot validate
  one route and one carrier.
- MoSPI has **not** endorsed APIx.

Growth is computed **within a single base year only**; the base is printed on
every row, because MoSPI publishes December 2014 under both base 2010 and base
2012 during the rebasing overlap.

## Regenerating

```bash
python tools/analysis/build_panel_json.py     # store    -> panel.json
python tools/analysis/build_dashboard.py      # contract -> dashboard.html
python tools/analysis/panel_report.py         # store    -> panel_report.txt
python tools/analysis/engine_demo.py --html   # fixture  -> engine-validation.html
```

```bash
git diff --exit-code data/     # no output = regeneration reproduced the content
```

Regeneration is **deterministic in content**. It is *not* byte-identical across
platforms: `.gitattributes` sets `* text=auto eol=lf`, so Git stores LF while
regeneration on Windows writes CRLF. Compare with `git diff`, which normalises —
not with `sha256sum`, which will differ by exactly the CR count.
